# Монитор цен yesoriginal.com.ua

Телеграм-бот, который каждый день в **08:00 по времени Чехии** проверяет цены на
[yesoriginal.com.ua](https://yesoriginal.com.ua/) по вашему списку товаров из Google Таблицы
и присылает сообщение, только если цена реально изменилась.

Работает целиком на GitHub Actions. **0 €/месяц.** Сервер не нужен.

---

## Что он делает

* берёт список товаров из вашей публичной Google Таблицы;
* отслеживает **только** те артикулы, что есть в таблице;
* отслеживает **только** те размеры, где `Кількість > 0`;
* хранит цену отдельно для каждой пары **артикул + размер**
  (на этом сайте цена реально отличается от размера к размеру);
* берёт **конечную цену**, которую платит покупатель, — не зачёркнутую и не процент скидки;
* сообщает и о снижении, и о росте цены, без минимального порога;
* при первом запуске просто запоминает цены и **ничего не присылает**;
* если изменений нет — **молчит**;
* по команде `/check` проверяет прямо сейчас и всегда отвечает.

Пример уведомления:

> 🔔 **Изменение цен на YesOriginal**
>
> 📉 **Цена снизилась**
> **Кросівки чоловічі Nike Court Vision Mid Grey DR7882-003**
> Артикул: `DR7882-003`
> Размер: EU 42
> Было: **3 999 ₴**
> Стало: **3 699 ₴**
> Изменение: **−300 ₴ (−7.50%)**
> [Открыть товар]
>
> Всего изменений: **1**

## Настройка с нуля

Инструкция рассчитана на человека, который не программирует. Всё делается в браузере,
ничего устанавливать не нужно.

### Шаг 1. Создать Telegram-бота

1. Откройте Telegram и найдите бота **@BotFather**.
2. Отправьте ему `/newbot`.
3. Придумайте имя (любое, например `Мой монитор цен`).
4. Придумайте username — он должен заканчиваться на `bot`, например `yesoriginal_price_bot`.
5. BotFather пришлёт сообщение со строкой вида
   `1234567890:AAH_kAkAyA-ToStRoKa_S_bukvami`.
   **Это и есть токен.** Скопируйте его.

> ⚠️ Токен — как пароль. Никому не показывайте и никуда не вставляйте, кроме GitHub Secrets.

### Шаг 2. Узнать свой Chat ID

1. Найдите **своего** только что созданного бота в Telegram и нажмите **Start**.
2. Напишите ему любое сообщение, например `привет`.
3. Откройте в браузере адрес (вместо `<ТОКЕН>` подставьте токен из шага 1):

   ```
   https://api.telegram.org/bot<ТОКЕН>/getUpdates
   ```

4. В ответе найдите `"chat":{"id":123456789,` — число `123456789` и есть ваш **Chat ID**.

   Если ответ пустой (`"result":[]`), напишите боту ещё раз и обновите страницу.

### Шаг 3. Проверить доступ к Google Таблице

Откройте таблицу → **Настройки доступа** → «Всем, у кого есть ссылка» → роль **Читатель**.

Из адреса таблицы понадобятся две вещи:

```
https://docs.google.com/spreadsheets/d/18G299yWL8DWkal7Ty_XFmzmI0ZWp4mBKFZonWpkBRvE/edit?gid=1297484631
                                        └──────── GOOGLE_SHEET_ID ────────┘             └ GOOGLE_SHEET_GID ┘
```

Для вашей таблицы они уже прописаны по умолчанию, менять ничего не нужно.

### Шаг 4. Создать репозиторий на GitHub

1. Зарегистрируйтесь на [github.com](https://github.com), если ещё нет аккаунта.
2. Нажмите **+** справа сверху → **New repository**.
3. Имя: `yesoriginal-price-monitor`.
4. Выберите **Public**.

   > **Почему публичный?** У публичных репозиториев минуты GitHub Actions
   > не тарифицируются вообще — бот получается бесплатным. В приватном репозитории
   > бесплатных минут 2000 в месяц, и проверка Telegram-команд каждые 5 минут их израсходует.
   > В репозитории лежат только цены — ничего секретного. Токен и Chat ID хранятся
   > **не в репозитории**, а в зашифрованных GitHub Secrets, и в публичном репозитории
   > они тоже недоступны посторонним.
   >
   > Если всё же хотите приватный — см. раздел «Приватный репозиторий» ниже.

5. Нажмите **Create repository**.
6. На следующей странице нажмите **uploading an existing file** и перетащите туда
   **всё содержимое** папки проекта (включая скрытые папки `.github` и файл `.gitignore`).
   Затем **Commit changes**.

   > Если скрытые папки не перетаскиваются, проще загрузить через GitHub Desktop
   > или попросить любого знакомого сделать `git push` — файлы уже готовы.

### Шаг 5. Добавить секреты

В репозитории: **Settings** → слева **Secrets and variables** → **Actions**.

Вкладка **Secrets**, кнопка **New repository secret** — добавьте два:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из шага 1 |
| `TELEGRAM_CHAT_ID` | число из шага 2 |

Вкладка **Variables**, кнопка **New repository variable** — добавьте два:

| Имя | Значение |
|---|---|
| `GOOGLE_SHEET_ID` | `18G299yWL8DWkal7Ty_XFmzmI0ZWp4mBKFZonWpkBRvE` |
| `GOOGLE_SHEET_GID` | `1297484631` |

### Шаг 6. Включить GitHub Actions

Вкладка **Actions** → кнопка **I understand my workflows, go ahead and enable them**.

Ещё нужно разрешить боту сохранять цены обратно в репозиторий:
**Settings** → **Actions** → **General** → раздел **Workflow permissions** →
выбрать **Read and write permissions** → **Save**.

### Шаг 7. Первый запуск

Вкладка **Actions** → слева **Daily price check** → кнопка **Run workflow** → **Run workflow**.

Проверка займёт 2–4 минуты. **Уведомлений не будет — это нормально.**
Первый запуск только запоминает текущие цены (см. ниже).

Что должно получиться: в папке `data/` появится обновлённый `state.json`,
а в истории коммитов — запись `chore(state): update prices`.

## Как работает первый запуск (baseline)

При самом первом запуске бот:

1. читает таблицу,
2. находит товары на сайте,
3. записывает текущие цены как «начальные»,
4. **ничего не отправляет в Telegram**.

Уведомления начинаются со второй проверки — иначе первое же сообщение было бы
списком из сотни товаров.

То же правило работает для **новых строк**: если вы завтра добавите в таблицу новый
артикул или новый размер, его цена сначала просто запомнится, без уведомления.

Пример:

```
День 1:  DR7882-003 | EU 42 | 2 990 ₴   → сохранено, тишина
День 2:  DR7882-003 | EU 42 | 2 690 ₴   → 📉 2 990 → 2 690 (−300 ₴, −10.03%)
```

## Ежедневная проверка

Каждый день, автоматически:

1. читается актуальная Google Таблица;
2. отбираются строки с `Кількість > 0`;
3. размеры группируются по артикулу;
4. на каждый артикул делается **один** запрос к сайту (даже если размеров 20);
5. со страницы берутся цены всех размеров;
6. остаются только ваши размеры;
7. цены сравниваются с сохранёнными;
8. состояние обновляется и коммитится;
9. если есть изменения — приходит **одно** сообщение со всеми;
10. если изменений нет — не приходит ничего.

### Про время 08:00

GitHub умеет запускать задачи только по UTC, а в Чехии время меняется дважды в год
(CET зимой, CEST летом). Поэтому workflow стартует **дважды** — в 06:00 и 07:00 UTC —
а скрипт сам смотрит на реальное время в `Europe/Prague` и работает только тогда,
когда там 08:00. Второй запуск завершается за пару секунд. Ничего настраивать
при переводе часов не нужно.

## Команда `/check`

Напишите боту в Telegram:

```
/check
```

Бот ответит `🔄 Запускаю проверку цен…`, а через 2–4 минуты пришлёт либо список изменений,
либо `✅ Проверка завершена. Изменений цен не обнаружено.`

**Задержка до 5 минут — это нормально.** GitHub Actions не может держать постоянное
соединение с Telegram, поэтому отдельный workflow раз в 5 минут забирает новые сообщения.
Если написать `/check` в 12:03, проверка стартует примерно в 12:05.

После `/check` новые цены становятся текущими сохранёнными. Повторный `/check`
про то же самое изменение уже не напишет.

Команды от посторонних чатов игнорируются: бот отвечает только на ваш `TELEGRAM_CHAT_ID`.

Ещё есть `/status` — покажет, сколько позиций отслеживается и когда было последнее обновление.

## Как изменить время проверки

Откройте файл `.github/workflows/daily-check.yml` прямо на GitHub (карандашик «Edit»).

Строки с расписанием:

```yaml
    - cron: '0 6 * * *'
    - cron: '0 7 * * *'
```

Это 06:00 и 07:00 **UTC**. Чтобы проверка шла, например, в 20:00 по Праге,
поставьте `'0 18 * * *'` и `'0 19 * * *'` и измените в том же репозитории переменную
`CHECK_HOUR` на `20` (Settings → Variables), либо отредактируйте `CHECK_HOUR` в `src/config.py`.

Правило простое: **два часа UTC подряд, из которых первый = нужный час минус 2.**

Чтобы изменить частоту опроса `/check` — файл `.github/workflows/telegram-poll.yml`,
строка `- cron: '*/5 * * * *'` (`*/10` = раз в 10 минут и так далее).

## Что бот НЕ присылает

Специально, чтобы не спамить и не создавать ложных срабатываний:

* «сегодня изменений нет» при автоматической проверке;
* «товар не найден на сайте»;
* «товар снова появился»;
* «изменилось название»;
* «появился/пропал размер»;
* уведомления при первом запуске;
* уведомления об изменении зачёркнутой цены или процента скидки.

---

## Защита от ложных уведомлений

Это главный приоритет проекта. Уведомление **не** отправляется, если:

| Ситуация | Что делает бот |
|---|---|
| товара нет на сайте | молча пропускает, старую цену не трогает |
| размера нет / он раскуплен | пропускает, **не** записывает 0 |
| сайт вернул ошибку 500/503/таймаут | пропускает этот товар, старая цена остаётся |
| страница пришла обрезанной | распознаёт и пропускает |
| цена не число, ≤ 0 или абсурдно большая | отклоняет, старая цена остаётся |
| ошибка на одном товаре | остальные товары проверяются дальше |

Изменение больше чем на 80 % помечается в логах как `АНОМАЛИЯ`, но уведомление
всё равно приходит — реальные скидки на этом сайте бывают и на −70 %.

## Как устроен сайт (для будущего обслуживания)

Это результат исследования реальных страниц, а не догадки.

**Движок:** OpenCart-подобный, HTML отдаётся сервером целиком. JavaScript и Playwright
не нужны. Cloudflare-защиты нет.

**Поиск товара.** Точное совпадение артикула даёт 302-редирект прямо на карточку:

```
GET /index.php?route=product/search&search=DR7882-003
    → 302 → /uk/krossovki-muzhskie-nike-court-vision-mid-grey-dr7882-003
```

Найденный URL кэшируется в `data/state.json`, и дальше бот ходит сразу на карточку —
это и быстрее, и уважительнее к `robots.txt` (там закрыты адреса с `search=`).

**Артикул** — в JSON-LD, поле `model`:

```json
{"@type":"Product","name":"Кросівки чоловічі Nike Court Vision Mid Grey DR7882-003",
 "model":"DR7882-003","offers":{"price":2990,"priceCurrency":"UAH"}}
```

Сопоставление идёт **только** по `model`. Название используется исключительно
для красивого текста уведомления.

**Цена по размерам** — каждый размер это радиокнопка со своими ценами:

```html
<input class="btn-check product-option" data-price="5990" data-special="2990" id="…-186394">
<label for="…-186394">42</label>
```

* `data-price` — зачёркнутая цена;
* `data-special` — цена со скидкой, **`0` означает «скидки нет»**;
* **конечная цена = `data-special`, если он > 0, иначе `data-price`.**

⚠️ `offers.price` из JSON-LD брать нельзя — это цена только предвыбранного
(самого дешёвого) размера. Для DR7882-003 сайт показывает 2990, но это цена размера 42,
а 43-й стоит 4090.

**Недоступные размеры** просто не выводятся в HTML.

**Два блока наличия.** У части товаров размеры разбиты на секции —
«В наявності (доставка 1-2 дні по Україні)» и «В наявності (безкоштовна доставка 3-7 днів з EU)» —
и один размер может быть в обеих с разной ценой. Бот берёт **первую** секцию
(быструю доставку по Украине) и пишет в лог, что размер встретился дважды.

## Что делать, если сайт изменит структуру

Признак: в логах массово `товар не найден` или `размер отсутствует на сайте`,
при этом на сайте товары открываются нормально. **Ложных уведомлений о ценах при этом
не будет** — бот в таких случаях молчит и сохраняет старые цены.

Порядок действий:

1. Откройте любую карточку товара, нажмите правой кнопкой → **Просмотр кода страницы**.
2. Найдите поиском (`Ctrl+F`) строку `product-option`.
   * **Нашлось, но атрибуты называются иначе** (например, не `data-special`) —
     исправьте имена в `src/parser.py`, функция `extract_size_offers`.
   * **Не нашлось совсем** — вёрстка размеров переделана; смотрите,
     чем её заменили, и правьте ту же функцию.
3. Найдите `"model"`. Если пропало — поменялся способ хранения артикула;
   правьте `extract_product_ld` в `src/parser.py`.
4. Проверьте, работает ли ещё редирект: откройте
   `https://yesoriginal.com.ua/index.php?route=product/search&search=DR7882-003`.
   Если редиректа нет — правьте `resolve` в `src/site.py`.
5. После правок обязательно прогоните тесты (см. ниже) и один раз запустите
   workflow вручную, посмотрев в логи.

Файлы `tests/fixtures/*.html` — это сохранённая настоящая вёрстка сайта.
Если она поменялась, обновите фикстуры и тесты вместе с парсером.

### Что хранится в `data/state.json`

```json
{
  "version": 1,
  "url_cache": { "DR7882-003": "https://yesoriginal.com.ua/uk/…" },
  "items": {
    "DR7882-003|42": {
      "article": "DR7882-003",
      "size_eu": "42",
      "current_price": 2690.0,
      "previous_price": 2990.0,
      "product_url": "https://yesoriginal.com.ua/uk/…",
      "product_name": "Кросівки чоловічі Nike Court Vision Mid Grey DR7882-003",
      "first_seen_at": "2026-09-03T06:00:11+00:00",
      "last_checked_at": "2026-09-04T06:00:47+00:00",
      "last_changed_at": "2026-09-04T06:00:47+00:00"
    }
  }
}
```

Ключ — `АРТИКУЛ|РАЗМЕР`. Файл коммитится в репозиторий после каждой проверки,
поэтому цены не теряются между запусками (у GitHub Actions нет своей постоянной памяти).
Оба workflow используют общий `concurrency`-замок и `git pull --rebase` с повторами,
так что одновременный запуск ежедневной проверки и `/check` файл не испортит.

## Приватный репозиторий

Если репозиторий приватный, минуты Actions тарифицируются (2000 бесплатных в месяц).
Опрос каждые 5 минут этого лимита не переживёт. Тогда в `telegram-poll.yml` поставьте:

```yaml
    - cron: '*/30 * * * *'
```

Это ~48 запусков в сутки ≈ 1400 минут в месяц вместе с ежедневной проверкой.
Расплата — `/check` будет отрабатывать до получаса.

## Известные ограничения

* **Задержка `/check` до 5 минут** — GitHub Actions не умеет держать вебхук.
